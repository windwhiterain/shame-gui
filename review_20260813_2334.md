## 1. Verdict

This is a small, opinionated, and internally coherent codebase (~11.6k lines). The core architecture — a unified state model where the app state and every map element are the same `#[derive(DagStruct)]` struct accessed through monomorphized `Port` handles behind a `DagStructRef` guard — is a genuinely clean idea, and it is executed with discipline: no `StateArena`/`Box<dyn Any>` runtime store, no trait-object downcasts in the hot path, write-based dirty tracking kept hidden inside the graph, and compile-time WGSL↔C layout verification in the derive. The test suite is strong for a project this size (pixel-exact goldens, per-key dirty-semantics tests, wire-layout tests).

The main debts are **documentation drift** (lib.rs/README describe a `StateArena` architecture that no longer exists), **copy-pasted math** (the pixel→NDC formula exists in ≥4 places despite the "single conversion point" claim), and a handful of **robustness gaps** (busy-wait surface acquire, silent readback failure, two snapshot tests pinned to system fonts). Nothing found blocks a release, but the items in §4 are worth fixing first.

## 2. What's good

### 2.1 The unified state model (`graph/`)
- `Port<D, S>` + `DagStructRef<S>` (port.rs, element.rs) is the right abstraction: one `Port` type works for the global state *and* collection elements, field access is monomorphized fn pointers (no downcast in the hot path), and `DagStructRef` never exposes the raw state — the only way to touch fields is through typed ports. This is a big improvement over the old `StateArena` design and deserves to be kept.
- Dirty/fired tracking is invisible to user code: `Port::write`/`read_mut`/`fire` mark sets shared with the graph; `Graph::tick` resets fired conditions at end-of-tick (graph.rs:399–404). The semantics are documented crisply (first-run unconditional, condition bypasses dirty, level-triggered sources need rising-edge detection).
- `add_map_node` (graph.rs:228–349) with structural key diff + per-key dirty records (`MapDirty<K>`/`ElemDirty`) is the most subtle code in the crate and it is well done: dirty is write-based, removed keys are dropped, and the map↔map cycle break in topo sort (graph.rs:112–113) lets chained map stages coexist. `tests/dynamic_map.rs` covers the edge cases (insert/remove granularity, chained stages, full-map refresh).

### 2.2 Derive macro engineering (`shame_gui_derive`)
- Compile-time `offset_of!` vs WGSL layout asserts (lib.rs:326–342 of the derive) with helpful error messages ("reorder fields or insert padding") are excellent — they catch the #1 class of GPU data bugs at build time.
- `#[state]` as an *attribute* macro that injects `__builtin` *before* derives run (lib.rs:721–760) is a clever ordering trick, and `Widget` auto-skips the injected field by type (field_type_is_builtin_state).

### 2.3 Batching (material.rs, app.rs)
- `InstanceArena` (free-list + grow-only buffer + CPU mirror + args buffer) with RAII `GpuInstanceBuffer` handles is compact and correct; `arena_free_reuses_space` test proves reuse. One `multi_draw_indexed_indirect` per group is the right design for many small objects.

### 2.4 Testing
- Snapshot goldens + `App::step()` CPU-only frame simulation give fast, deterministic UI tests. `tests/instance.rs` (wire layout) and `tests/dynamic_map.rs` (dirty semantics) are notably thorough. `tests/widget.rs` covers the number/string widgets including focus routing.
- Defensive comment in `snapshot_map_batched_indirect.rs` (non-overlapping stripes immune to HashMap iteration order) shows awareness of flakiness sources.

### 2.5 Misc
- `ErasedKey` (material.rs:530–564) solves the dyn-compatibility problem of `PartialEq`+`Hash` through monomorphized fn pointers — clean workaround.
- `dual.rs`'s `reinterpret_val` policy ("never write relational bounds") keeps the CPU/GPU dual-target code tractable; GPU-side call sites are confined to the two shader materials.

## 3. Architecture-level observations

1. **The framework is immediate-mode UI + dataflow (retained) state.** Widgets are pure per-frame walkers (layout → render → events) over a DAG-held state. This hybrid is coherent, but it means widget rendering and the DAG tick are *two separate walks* over the same state, which is the root cause of the documented one-frame lag for `ViewportRect` (widget writes during render; DAG reacts next tick). The framework papers over it with `compare_snapshot_frame2` instead of addressing the ordering. If a widget writes and the DAG must react in the same frame, consider ticking the DAG a second time after the render walk (cheap when no ports are dirty) rather than shipping a "run two frames" test idiom.
2. **Two render paths with divergent allocation behavior.** Render slots upload per-object GPU buffers via DAG nodes with a `BufferPool`; the fast path reallocates its per-material buffer on every growth; batched groups use the arena. That's three buffer-management strategies for one concern. It works, but each has its own growth/leak semantics; a note in the module docs explaining *when to pick which* would help users.
3. **`add_map_node`'s `elem_out` parameter is decorative** (graph.rs:348: `let _ = elem_out;`) — it exists only to pin the element type at the call site; actual per-element-port propagation happens through the shared dirty set. This is a subtle API surface: a caller can pass a wrong `elem_out` group and get no compile error *and* no effect. Either document this loudly or find a way to make it part of the contract (e.g. have the eval's writes define the element outputs, which they already do).
4. **Per-frame taffy tree construction.** `container_table_rects` builds a fresh taffy tree on every render walk *and* every event walk (render.rs:97, context.rs:203/269). For the target scale (a few hundred widgets) this is fine, but it's the first thing to cache when performance matters.

## 4. Concrete issues (ranked)

### High

1. **Busy-wait surface acquire loop** — `gpu.rs:78–98` loops up to 100 times on `Occluded`/`Timeout` with no sleep, then `assert!`s. An occluded window (minimized, covered, or a slow compositor) spins the CPU for 100 `get_current_texture` calls *per frame*. Replace with a `std::thread::sleep` (a few ms) inside the retry loop, and make the terminal failure a `panic!` with context instead of a debug-only assert.

2. **Silent empty-frame readback** — `capture.rs:120–122` returns `vec![]` on map failure; the caller (`tests/common/mod.rs`) then fails with a confusing downstream panic. Return a `Result` or panic with a message naming the failure; the readback API is public and documented as a generic utility.

3. **Two snapshot tests use system fonts** — `snapshot_blend.rs:13` and `snapshot_rects.rs:13` construct `TextSystem::new()` (system font discovery) while every other snapshot uses the embedded Inter via `common::test_text_system()`. The two goldens are therefore machine-dependent — the same class of nondeterminism the common module exists to prevent. Switch them to the embedded font and re-accept the goldens.

4. **Number widget commits unconditionally on Enter** — `number.rs:166–171` always `self.write(state, value)` even when the value is unchanged, marking the port dirty and re-running the DAG. `string.rs:124–128` guards with `new != old`; `number.rs` should do the same. (Same class: clicking outside an editing field silently drops input in both number.rs:136–138 and string.rs:97–98 with no commit/cancel feedback — at minimum document the behavior.)

### Medium

5. **Stale architecture docs (the biggest doc debt).** `lib.rs:10, 23, 42` and `README.md:13, 67, 75` describe a `StateArena` that no longer exists anywhere in the code; `README.md:50` references `build_state_ports` (no such function; the API is `X::ports()`). lib.rs calls the framework "retained-mode" while README says "immediate-mode". Also README links `anomalyco/shame` while the workspace and lib.rs use `windwhiterain/shame`. Fix these before they mislead the next contributor.

6. **Pixel→NDC formula is copy-pasted despite the "single conversion point" claim.** `dual::pixel_to_ndc`/`rect_to_ndc` is the CPU path, but `shader/rect.rs:54` + `shader/wireframe.rs:40` each call it via a **self-referential `shame_gui::dual::...` path** (works only because of `extern crate self as shame_gui` — brittle; should be `crate::dual::...`), and `examples/push_constant.rs:67` re-implements the formula by hand. The duplicated `RectGpu` snippet in both shaders is another instance. Extract one GPU-side helper (the `RectGpu`-build + `rect_to_ndc` pair) and use it from both materials; have the example use `dual::rect_to_ndc` too.

7. **Magic alpha-discard 0.5 in three places** (rect.rs:71, wireframe.rs:55, push_constant.rs:83) — a named constant in `shader/mod.rs` would do; note the wireframe material has `blend: None`, so this discard is the *only* transparency mechanism for outlines.

8. **`check.py` mutates the tree.** It runs `cargo fix --allow-dirty --all-targets` as a "verification" step — if a fix fails midway the tree is left half-modified, and it can touch `Cargo.lock`. A check script should be read-only (`cargo check` + `cargo fmt --check`). Also the workspace `[patch]` (Cargo.toml:21–24) points at a sibling `../shame` checkout — the build silently depends on a directory outside the repo, and the `git+ssh` deps break builds without SSH access. The `.cargo/config.toml` override (documented, not committed) is fine, but consider committing a `--locked` CI path.

9. **Stray committed file** — `.compose/brainstorm/1687-1786275401/state/server-stopped` (committed in 107f985) is tool state, not project content. Remove from tracking.

10. **Dead code.** `gui/layout.rs:10 child_rects` has zero callers (public, so it's silently exported API); `bool.rs:15/74 BoolWidgetData.hovered` is written but never read (the checkbox has no hover feedback — either render it or drop the field). `tests/common/mod.rs` `compare_snapshot_frame2` is flagged unused by the compiler warnings (used only by `snapshot_viewport_rect`); the `main`-never-used warnings across snapshot binaries are worth a cleanup pass or an explicit `#![allow]` note.

### Low / polish

11. `gpu.rs:37` `max_immediate_size: 256` — undocumented magic; the `INDIRECT_FIRST_INSTANCE` feature is required but a device that lacks it fails with a bare `unwrap()` at gpu.rs:32–40 (add an `expect` naming the feature).
12. `text.rs` — line-height `(font_size * 1.2).ceil()` duplicated at :130 and :230; `default_color` truncates `(r * 255.0) as u8` with no rounding/clamp (:269–274); glyphs past the depth table silently fall back to z 0.5 (:287).
13. `vec2.rs:73` displays `{:.1}` (one decimal) so 0.05 renders as "0.1" — inconsistent with `number.rs`'s full `to_string()` display; also no error state on parse failure (unlike number.rs).
14. `bool.rs:73–76` returns `Consumed` for every `MouseMove`, even outside its rect — check it doesn't starve hover for widgets drawn after it in the container walk.
15. Z-layer magic: `Z_MENU = 0.05` is "on top" only under the smaller-z-closer convention, and collides with user z=0.05 in `examples/rects.rs`; the split clamp `ratio.clamp(0.1, 0.9)` (viewport/layout.rs:102) is undocumented behavior. Style constants are otherwise well centralized — a short comment in `style.rs` on the z convention (already half there) would close the loop.
16. `Tab` layout uses only the *active* tab's preferred size (viewport/layout.rs:81–91) — switching tabs can jump the container size; document as intended or size on the max.
17. Workspace vs crate-level deps are split inconsistently: taffy/glyphon/cosmic-text are pinned inline in `crates/shame-gui/Cargo.toml` while wgpu/winit/etc. live in `[workspace.dependencies]`.
18. Minor duplication: `form.rs`'s `num`/`unum` helpers, the near-identical instance structs across three examples, `render_with_dag` as a pure wrapper over `render_impl` (gui/viewport/mod.rs:54–100).
19. Missing-golden auto-accept in `tests/common/mod.rs:128–136` silently turns a first run into the golden — documented, but a deleted golden would be silently re-created; an env-var guard (`SHAME_GUI_ACCEPT=1`) would be safer.
20. Snapshot comparison is pixel-exact with zero tolerance (common/mod.rs:164) — the embedded font mitigates driver differences, but a tiny tolerance or a documented "re-run the single binary" note would help non-Intel GPUs.

## 5. Things deliberately *not* flagged (design decisions, per AGENTS.md)

- No `Result`/error handling anywhere; panic-fast with `.expect("...")` — documented and consistently applied.
- No blending/z-sorting; `Depth24Plus` + `less_equal`, smaller-z-closer — consistent across rect + text passes.
- `Canvas` being `pub(crate)` and the draw helpers not exposed.
- Per-key `MapEntry` Drop-time dirty recording via `Rc<RefCell<...>>` — correct given the borrow structure, and well-commented.
- `unsafe` in `AnyWidget` (`UnsafeCell`) and the `ptr::read`/`ptr::write` in `execute_split` (context.rs:234–243) — both are the standard way to do this in safe-looking APIs and are commented.
