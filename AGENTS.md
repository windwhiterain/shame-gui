## The unified state model (core architecture)

**A state is any `#[derive(DagStruct)]` struct.** The global app state and every collection element are the *same kind of thing*: a struct whose fields are accessed through one [`Port<D, S>`] type. There is no `StateArena`/`Box<dyn Any>` runtime store — values live in a plain struct, and field access is monomorphized fn pointers generated by the derive (no downcast).

- `Port<D, S>` — reads/writes field `D` of state `S`. `S` **defaults to [`BuiltinState`]**, so a bare `Port<f32>` = `Port<f32, BuiltinState>`. Methods: `read(&DagStructRef<S>) -> &D`, `write(&mut DagStructRef<S>, D)`, `read_mut(...)`. Manual `Clone`/`Copy` (fn pointers).
- `DagStructRef<S>` — the guarded `&mut S` wrapper every node/eval receives. **No `Deref` to `S`**; the only way to touch fields is through `Port` handles. Carries dirty/fired tracking (shared with the graph via `Rc<RefCell<HashSet<PortId>>>`; `DagStructRef::new` gives isolated sets for widget unit tests).
- `DagStruct` (trait) + `#[derive(DagStruct)]` — generates `{Name}Ports { field: Port<FieldTy, Self>, ... }`, `impl PortGroup<Self>`, `impl PortValue`, and **`Self::ports() -> {Name}Ports`** (an inherent method, so no trait import needed). Only structs used as a *state* derive this; primitives are just `PortValue`.
- [`BuiltinState`] (`graph/state.rs`) — the built-in state: source fields (`framebuffer_size`, `mouse_pos`, `mouse_down`, `scroll_delta`, `delta_time`, `elapsed`) + render fields (`fills`, `outlines`, `texts`). `App<BuiltinState>` uses it directly.
- `AppState` trait + `#[state]` attribute macro — a custom app state is declared as a plain struct of its own fields with `#[state]` prepended; the macro injects a reserved `pub __builtin: BuiltinState` field and generates the `AppState` impl (`builtins()`/`builtins_mut()`/`source_ports()`/`render_ports()`). Source/render ports of the injected builtin use reserved `PortId` ranges (`SOURCE_PORT_BASE` / `RENDER_PORT_BASE`) so they don't collide with user field ids (which start at 0). `#[derive(Widget)]` auto-skips the injected field (detected by type), so no `#[widget(skip)]` is needed for it.

## Deliberate design decisions — do not "fix"

- **No error handling**: no `Result`/`Error`; unwrap/expect. Panic-fast.
- **No blending, no z-sorting**: `Depth24Plus` with `less_equal`. **Smaller z = closer**. Shared across rect + text passes.
- **Physical pixel coords, y-down**. `Rect::to_ndc(fb: Vec2u)` is the only NDC conversion.
- `Canvas::render()` reads render-slot data from state ports (gpu buffer, bind group, constant). Render slots do NOT own GPU buffers — DAG upload/bind nodes write them into `Option<Arc<...>>` state fields. Fast-path (widget fills/outlines) uses `Canvas::add_instance()` + `set_push_constant()` directly.
- `Material` requires `Eq + Hash + Clone`; registration dedups by value. One pipeline + draw call per material.
- **`#[derive(Widget)]` does NOT generate a `Widget` impl** — it generates `into_viewport_nodes() -> Vec<(String, ViewportNode<Self>)>` and `into_tab_nodes() -> Vec<(String, Vec<(String, ViewportNode<Self>)>)>`. Fields marked `#[widget(skip)]` (e.g. the injected `__builtin: BuiltinState`, render-object ports) are omitted; `#[widget(selector = "map_field")]` on a `String` field swaps in a `MapSelector` (see "Selector widget"). `into_viewport_nodes()` calls `Self::ports()` internally, so it takes no args and needs no arena.
- **`#[derive(Widget)]` requires `#[derive(DagStruct)]`** on the same struct.
- `Gui.focus: Option<u64>` — direct WidgetNode ID focus.
- `Canvas` is `pub(crate)` — don't expose it or draw helpers.
- Dirty/fired tracking is **hidden inside the graph** (`Rc<RefCell<HashSet<PortId>>>` shared with `DagStructRef`). User code never sees a dirty flag; `Port::write`/`read_mut`/`fire` mark the sets automatically.

## `#[derive(GpuStruct)]` contract

- One trait, one derive. `align(16)` = instance struct (full serialize, real `make_bindings`); no `align(16)` = field type (flat `bytes_of`, `Gpu = sm::Struct<NameGpu>`).
- Wire size differs: instance → div-ceil-16; field → max member alignment.
- Derive also generates `Pod` + `Zeroable` — do NOT hand-write them.
- `serialize` pads grow-only to wire-size boundary.
- `Canvas.clear()` empties fast-path CPU buffers (capacity retained) but skips render slots; GPU buffer grow-only.

## CPU/GPU dual-target system (`dual.rs` + `#[derive(GpuStruct)]`)

**Philosophy: one function, two backends, no relational bounds.**

- `ScalarLike<const GPU: bool>` — scalar + `from_f32`. CPU: `f32`, GPU: `sm::f32x1`.
- `FloatScalar<const GPU: bool>` — `ScalarLike` + arithmetic. Blanket impl.
- `Vec2Like<const GPU: bool>` — 2D vector; CPU `Vec2`, GPU `sm::f32x2`.
- `#[derive(GpuStruct)]` generates `{Name}Like<const GPU: bool>` with one associated type + getter per field, implemented for the CPU struct (`Like<false>`) and GPU twin (`Like<true>`).
- `reinterpret_val`/`reinterpret_ref`/`reinterpret_mut` — `unsafe` bridges between associated types known to be the same concrete type. **Policy: never write relational bounds** (`V1::Scalar = V2::Scalar`); resolve locally with `reinterpret`.
- Reference: `pixel_to_ndc`, `rect_to_ndc` in `dual.rs`; GPU-side call sites in `shader/rect.rs`.

## DAG system (`graph/`)

**Core abstractions:**
- `PortValue: Clone + Default + 'static` — types flowing through ports (f32, u32, bool, String, `()`, `Vec<RectEntry>`, `Vec<TextObject>`, `HashMap<K,V>`, `InstanceBuffer<I>`, any `Material`, structs via `#[derive(DagStruct)]`).
- `PortId(u64)` — field index within a state `S`. Only meaningful relative to its state type (each state numbers fields from 0; injected `BuiltinState` fields use reserved high ranges via the `#[state]` macro).
- `Port<D, S = BuiltinState>` — typed field handle (see "unified state model").
- `PortGroup<S>` — structural group of ports (single `Port`, `()`, tuples 2–4, `{Name}Ports`, `IdGroup`). `leaf_count()`, `extend_ids(&mut Vec<PortId>)`, `ids()`.

**Graph construction (`app.graph_mut() -> &mut Graph<S>`):**
- `Graph::new()` — no args (source/render ports come from `S::source_ports()`/`render_ports()`).
- `graph.add_node(eval, inputs, outputs, condition)` — `eval: FnMut(&mut DagStructRef<S>, Option<&sm::Gpu>)`. `inputs`/`outputs: impl PortGroup<S>`; `condition: Option<Port<bool, S>>` makes it event-driven.
- `graph.add_map_node(map, global_in, global_out, elem_in, elem_out, eval)` — dynamic fan-out (below).
- `graph.add_map_tree_node(map, path, trigger, leaf)` — **arbitrary-depth** fan-out over a map hierarchy (below).
- `graph.with_state(&mut state) -> DagStructRef<S>` — wraps the state, routing writes into the graph's dirty/fired sets (used by `App` to write source fields, and by the GUI render walk).
- `Graph::tick(&mut self, state: &mut S, gpu: Option<&sm::Gpu>)` — runs dirty/condition/new nodes in topo order, then resets fired conditions.

**Execution semantics:**
- New nodes run unconditionally on their first tick, then only when any input port is dirty.
- Condition nodes run **only** when their condition port reads `true` (dirty ignored, no auto first-run).
- `Port<bool, S>::fire(&mut DagStructRef)` writes `true` + marks fired; `Graph::tick` resets all fired conditions to `false` at end-of-tick.
- **Level-triggered sources need rising-edge detection** in the fire node's closure (see `examples/click_rects.rs`).

### Dynamic HashMap fan-out — `Graph::add_map_node`

```rust
graph.add_map_node(
    map,            // Port<HashMap<K, E>, S> — mutated in place
    global_in,      // PortGroup<S> — a dirty global input → full refresh
    global_out,     // PortGroup<S> — topology (global writes)
    elem_in,        // PortGroup<E> — element read ports
    elem_out,       // PortGroup<E> — element write ports
    |gref, gpu, key, eref: &mut DagStructRef<E>| { /* process one element */ },
);
```

- The node keeps a private `known_keys: HashSet<K>` and **diffs structurally** against the map each tick (plus per-key dirty records via `snapshot_map_dirty`/`ensure_elem_ports`), so **only changed keys are reprocessed**. Removed keys are dropped from the output.
- `E: Clone + 'static` (no `PartialEq` needed). The eval clones each changed element, wraps it in a `DagStructRef<E>` that **shares the element's port dirty set**, runs the closure, and writes the result back. `global_in`/`global_out`/`elem_in`/`elem_out` are separate parameters because `S` and `E` are different types.
- **Widget-side per-key access — `MapEntry::dagref()`**: widget code (holding `&mut DagStructRef<S>`, no map-node eval) borrows one element through a `DagStructRef<V>` that **shares the element's port set and nested map-dirty store with the graph**. The borrow itself marks nothing (unlike `read_mut`, which marks the whole element `full` on drop); only the ports used through it record — so `inner_map.get/insert/remove` on a nested map port records that inner key and the tree reprocesses **exactly that cell**, not the whole layer subtree. Marks the map port dirty so the nodes run. Chain one `dagref` per level to reach arbitrary depth. Reference: `tests/nested_tree.rs` (`widget_side_*` tests). `dagref_unmarked()` is the same borrow without the map-port mark — for read-mostly widget paths (render) that mark the port only when a write actually happened (see "Map widget").
- Reference: `examples/dynamic_map.rs` + `tests/dynamic_map.rs`.

### Arbitrary-depth fan-out — `Graph::add_map_tree_node` + `RenderPath`

One **flat** node descends a `HashMap` hierarchy of any depth: the path type (`RenderPath<E>`; `MapPath { map, next }` per map level, `FieldPath { field, next }` per plain struct field, `LeafMarker<L>` at the bottom) is `Clone`, and the node's eval fans out level by level through the recursive nested dirty records (`ElemDirty.nested`), so only changed subtrees reprocess. The leaf eval `FnMut(&mut DagStructRef<P::Leaf>, Option<&Gpu>)` runs per changed bottom element.

- Fresh element (insert / overwrite / whole-element mutation / whole-map write / first run) → **full-subtree pass**; the freshness flag threads down every level.
- `trigger: PortId` — a leaf port id checked against each element's port-dirty set: at the top level it re-triggers an element a chained stage wrote (leaf-at-top paths pass the leaf read port, e.g. `cpu_buffer`); at the bottom level it is checked against each leaf's ports, so a leaf read-port write (chained stage or widget-side `MapEntry::dagref` access) reprocesses exactly that leaf.
- Per-level filter also checks the element's nested record against the child's map id (same-tick inner-map writes by earlier stages).
- **`FieldPath` (struct-field level)**: crosses a plain struct field between maps (e.g. `groups → audio (struct) → presets (map)`). The field's dirty record is the same `ElemDirty` the widget-side `Port::with_field_ref` shares, so a leaf edit under the field reprocesses exactly that leaf; a whole-field write (`Port<T, S>::write`/`read_mut` — the `DagStruct` derive's `note_full_write` marks the record `full`) reprocesses the whole subtree; no add/remove semantics. `map_id()` reports the field's id, so the parent level's nested-record check works unchanged.
- The node tags itself as a map node over the top map (map↔map cycle breaking, insertion order governs).
- Reference: `tests/nested_tree.rs` (depth 1/2/3 + chained stages + widget-side per-cell writes + `FieldPath` crossing struct fields).

**Widget → DAG bridge:** widgets write through `DagStructRef` (`Port::write`), auto-marking ports dirty; the graph re-runs nodes reading them on the next tick. No manual `mark_dirty` wiring.

**DAG-produced custom render objects** (`App::register_render_object`): material + instance buffer + push constant + gpu buffer + bind group are all **declared fields of `S`**. Two internal nodes upload the buffer and build the bind group. Canvas reads them from the state each frame.

## Batched render objects (indirect draw)

All batched paths funnel into one shared `InstanceArena` (grow-only storage buffer + free-list + indirect args buffer) per group. Canvas builds the bind group (no DAG bind node). `gpu.rs` requires `Features::INDIRECT_FIRST_INSTANCE`.

A `BatchedGroupSlot` is **(arena, material, batches)** — `read_batches: Box<dyn Fn(&S) -> Vec<DrawBatch>>` read from the state at render time. A `DrawBatch` is a push constant + the arena slots drawn with it; the canvas builds the args buffer **in batch order** and issues **one `multi_draw_indexed_indirect` per batch**. Static/flat registrations produce a single batch (one dispatch, as before); a render tree produces one batch per top-level element.

- `register_render_objects_batched<M>(material, constant, cpu_buffers)` — **static**: a fixed list of `Port<InstanceBuffer<M::Instance>, S>`; one upload `add_node` per object into its own arena slot. Reference: `tests/snapshot_batched_indirect.rs`.
- `register_map_render_objects_batched<M,K,E>(map, material, constant, cpu_buffer, gpu_buffer)` — **dynamic**: `HashMap<K,E>` where each element carries `cpu_buffer: InstanceBuffer<M::Instance>` (user-filled) + `gpu_buffer: Option<GpuInstanceBuffer>` (framework-written). One `add_map_node` uploads per changed key; `GpuInstanceBuffer` is RAII (`Rc` + `Drop` → `free_slot`), so removing a key releases its slice automatically — **no reconcile node**. Reference: `examples/dynamic_map_gpu.rs` + `tests/snapshot_map_batched_indirect.rs`.
- `register_render_tree_batched<M,K,E,P>(material, top_map, constant, path, cpu_buffer, gpu_buffer)` — **render tree**: the top map's elements each provide `constant: Port<M::PushConstant, E>`; the leaves of the `path` hierarchy provide the instance ports. One indirect dispatch per top-level element (its constant + every leaf's slots in its subtree). Built on `add_map_tree_node` (upload per changed leaf) + a render-time batch walk (`RenderPath::collect`); the batch list is derived from the state each frame, so constant changes and insert/remove show up with zero DAG wiring. `P::Leaf` types the leaf ports, so the same call covers 1-level (bare `LeafMarker`) to N-level trees, with `FieldPath` crossing plain struct fields between maps. Reference: `examples/render_tree.rs` + `tests/snapshot_tree_batched_indirect.rs` (per-group tint constants verified by pixel assertions; the scene descends `FieldPath` → `MapPath`).
- One draw = one bind group + one push constant per batch: batch only objects/elements sharing the same material value; push constants may vary per batch. `ViewportParams` implements `PortValue`, so the built-in `RectMaterial`/`WireframeMaterial` work in the static/flat APIs.

## ViewportRect — custom widget rendering (`gui/primitives/viewport_rect.rs`)

`ViewportRect` is a passive data-tap: `Port<ViewportRect, S>` implements `Widget<S>`, and its `render` writes the layout-assigned `Rect` back into the state each frame. A DAG node reads it, converts to NDC, and feeds a custom material's push constant. **One-frame lag** (widget writes during render; DAG reacts next tick → use `compare_snapshot_frame2`). ## Widget layer (`gui/widget.rs`)

- `Widget<S>: 'static + Clone` — `type Data: WidgetData`, `layout_style(&DagStructRef<S>, &Data)`, `render(&mut DagStructRef<S>, &Data, Rect, &mut RenderContext)`, `on_event(&mut DagStructRef<S>, &mut Data, &InputEvent, Rect)`. `self` is the widget handle (e.g. `Port<f32, S>`); read/write through `DagStructRef`.
- Primitive `Widget<S>` impls: `Port<f32, S>`/`Port<u32, S>`/`Port<i32, S>`/`Port<usize, S>` (number), `Port<String, S>` (string), `Port<bool, S>` (bool), `Port<Vec2, S>` (vec2), `Port<ViewportRect, S>` (viewport_rect). All are blanket `impl<S: 'static> Widget<S> for Port<T, S>`. Plus the field widget's blanket `impl<S, T: WidgetElement + PortValue> Widget<S> for Port<T, S>` (see "Field widget") — it does not overlap: no primitive/HashMap type implements `WidgetElement`.
- `RenderContext { fills, outlines, texts, framebuffer }` — no `add_render_object()`; custom rendering goes through DAG + `register_render_object`.
- `AnyWidget<S>` — type-erased handle + data (fn pointers over `W: Widget<S>`); `WidgetNode<S>` = `AnyWidget<S>` + `id` (no `port_ids` — accessors are in the port, not an id list). `duplicate()` clones the handle with fresh data.

## Map widget (`gui/primitives/map.rs`) — `Port<HashMap<String, T>, S>`

A collapsible key-value list: one header row per key (expander + key label + delete `x`), a bottom add row (`[key input][+]`), and clicking a header expands the entry into its element form — the labelled field widgets from `T::into_viewport_nodes()` (requires `T: #[derive(DagStruct, Widget)]`).

- `WidgetElement` trait (`gui/widget.rs`) — the trait form of `into_viewport_nodes()`; `#[derive(Widget)]` emits the impl alongside the inherent method (both modes, tab included). This is how the map widget builds its per-field template generically.
- **Per-element duplicated template**: expanding a key deep-clones the template (`deep_duplicate_viewport`) so simultaneously expanded elements get fresh `Data` and unique `WidgetNode` ids (no shared editing buffers, per-element `sub_focus`). Collapse drops the copies.
- **Dirty contract (tested in `tests/map_widget.rs`)**: `insert` records `added` (new key processed once); `remove` records `removed` (no reprocess, downstream re-runs); child-widget edits go through `MapEntry::dagref_unmarked` + a post-walk check (`ensure_elem_ports` shared set non-empty → mark the map port) so **render/layout never wake the map nodes** — a clean tick reprocesses nothing. Element types may contain nested maps: the recursion inherits per-key/`nested` tracking, so add/remove/edit at any depth reprocesses exactly that subtree cell.
- Layout heights: `layout_style` computes from key count + expanded set, using per-key section heights measured at render (fallback = `template.len()` rows before the first render). Reference: `examples/map_widget.rs` + `tests/snapshot_map_widget.rs`.

## Selector widget (`gui/primitives/selector.rs`) — `MapSelector`

A dropdown that edits `Port<String, S>` constrained to the keys of a `Port<HashMap<String, T>, S>` — a **two-port handle**. Two construction paths:

- **Derive attribute (same struct)**: `#[widget(selector = "teams")]` on a `String` field makes `into_viewport_nodes()` emit a `MapSelector` over the named `HashMap<String, T>` field (validated at compile time: the field must be `String`, the named field must exist and be `HashMap<String, _>`; mutually exclusive with `#[widget(skip)]`). Works in table, tab and `WidgetElement` (map element) modes.
- **Manual (cross-struct)**: `MapSelector::new(map, key)` wrapped in a `WidgetNode` by hand — for selectors whose map lives in a different state than the annotated field.

Header row shows the current value (a "(none)" placeholder when empty); clicking it expands the **sorted** key list inline (layout height grows, like the map widget); clicking a row writes that key. Mouse-only (`selectable() = false`); hover highlight via broadcast `MouseMove` (data-only).

- Constraint semantics: empty = valid "unset"; any other value must be a key. **`render` auto-resets a stale value** (its key removed elsewhere) to `""` — writes once, converges next frame, so normal frames stay clean.
- Dirty boundaries: render/layout/events only *read* the map (untracked — the map port is never marked); a selection writes the key port only when it actually changes; the stale reset wakes key readers exactly once.
- Reference: `examples/selector.rs` (derive attribute) + `tests/selector.rs` + `tests/snapshot_selector.rs`.

## Field widget (`gui/primitives/field.rs`) — `Port<T, S>`

A `#[derive(DagStruct, Widget)]` struct used as a **plain field** of another state renders its own labelled rows inside the parent's table — widget-struct nesting without a HashMap wrapper. The derive needs no changes: the blanket `impl<S, T: WidgetElement + PortValue> Widget<S> for Port<T, S>` (legal inside shame-gui; the orphan rule blocks it in user crates) makes every such field satisfy the derive's per-field `Widget` bound automatically. Nesting is recursive (a nested field may itself contain nested fields or maps).

- **The bridge — `Port::with_field_ref`** (`graph/port.rs`): borrows the field and runs the sub-walk on a `DagStructRef<T>` tracking into a **shared per-field record** (an `ElemDirty` keyed by the field's id in the state's dirty store — get-or-create via `DagStructRef::ensure_field_ref`), then marks the field port only if a sub-port was actually written. Sharing is what lets render-tree field steps ([`FieldPath`]) consume leaf writes (a leaf edit reprocesses exactly that leaf); without a tree, the record is just a write-detector. `T`'s `PortId`s (numbered from 0, like `S`'s) never enter the graph's flat set — no collision. The post-walk mark is **coarse** for plain `add_node` readers: any sub-write (including one inside a nested map) wakes as "whole field changed" on the field port — DAG nodes reading `Port<T, S>` re-run; per-leaf precision is the render-tree (`FieldPath`) feature. A whole-field write (`Port<T, S>::write`/`read_mut`) marks the record `full` via the derive's `note_full_write` override.
- **Data + layout**: `FieldWidgetData<T>` holds the `T::into_viewport_nodes()` template, the content height measured at render (fallback = shared `template_height` in `primitives/mod.rs`, also used by the map widget), and a `sub_focus` for the nested table. Render/events reuse `container_table_rects` + `walk_render`/`walk_event` under the bridged ref — the map widget's expanded-section machinery without the header/add rows.
- **Dirty contract (tested in `tests/field_widget.rs`)**: render/layout never mark (read-only walks leave the fresh set empty); a child edit wakes the field reader once; a 3-level edit (`Deep { bus: Bus { fx: Fx } }`) wakes the outer field; a map edit inside a nested struct wakes the field (the map's per-key record lives in the bridged fresh nested store, its `insert` marks the map port in the fresh set). Reference: `examples/field_widget.rs` + `tests/snapshot_field_widget.rs`.

## Testing quirks

- `App::step(inputs, dt, elapsed, cursor, fb_size)` — CPU-only frame simulation; derives `mouse_down`/cursor from `inputs`.
- `AppRunner<S>::after_tick(&AppContext<'a, S>) -> Vec<InputEvent>` — events injected next `step()` (one-frame lag). `AppContext` exposes `state: &S`, `graph: &Graph<S>`, `gui: Option<&Gui<S>>`.
- Snapshot tests are their own binaries; goldens auto-accept on first run.
- GPU snapshot binaries run in parallel under `cargo test`; rarely a first-frame capture reads a not-yet-sized surface and panics with a size mismatch. Re-run the single failing binary to confirm before treating it as a regression.
- Widget unit tests: `DagStructRef::new(&mut state)` gives isolated dirty tracking; call `port.on_event(&mut r, &mut data, &event, rect)`.
- Scene functions must use `app.state_mut()` (not a separate local state) — ports reference `S` by type, and a mismatched state produces the wrong accessors at render time.

## shame EDSL gotchas

- Comparisons are methods: `x.lt(y)`, `x.le(y)` — `x < y` does not compile.
- `shame_wgpu::bind_group!` generates `{Name}Resources`.
- Generated code uses `::shame_gui::...` and `shame::__private::...` — user crates must depend on `shame` directly.
- Reference EDSL: `crates/shame-gui/src/shader/rect.rs`.
