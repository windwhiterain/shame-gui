## The unified state model (core architecture)

**A state is any `#[derive(DagStruct)]` struct.** The global app state and every collection element are the *same kind of thing*: a struct whose fields are accessed through one [`Port<D, S>`] type. There is no `StateArena`/`Box<dyn Any>` runtime store — values live in a plain struct, and field access is monomorphized fn pointers generated by the derive (no downcast).

- `Port<D, S>` — reads/writes field `D` of state `S`. `S` **defaults to [`BuiltinState`]**, so a bare `Port<f32>` = `Port<f32, BuiltinState>`. Methods: `read(&DagStructRef<S>) -> &D`, `write(&mut DagStructRef<S>, D)`, `read_mut(...)`. Manual `Clone`/`Copy` (fn pointers).
- `DagStructRef<S>` — the guarded `&mut S` wrapper every node/eval receives. **No `Deref` to `S`**; the only way to touch fields is through `Port` handles. Carries dirty/fired tracking (shared with the graph via `Rc<RefCell<HashSet<PortId>>>`; `DagStructRef::new` gives isolated sets for widget unit tests).
- `DagStruct` (trait) + `#[derive(DagStruct)]` — generates `{Name}Ports { field: Port<FieldTy, Self>, ... }`, `impl PortGroup<Self>`, `impl PortValue`, and **`Self::ports() -> {Name}Ports`** (an inherent method, so no trait import needed). Only structs used as a *state* derive this; primitives are just `PortValue`.
- [`BuiltinState`] (`graph/state.rs`) — the built-in state: source fields (`framebuffer_size`, `mouse_pos`, `mouse_down`, `scroll_delta`, `delta_time`, `elapsed`) + render fields (`fills`, `outlines`, `texts`). `App<BuiltinState>` uses it directly.
- `AppState` trait + `#[state]` attribute macro — a custom app state is declared as a plain struct of its own fields with `#[state]` prepended; the macro injects a reserved `pub __builtin: BuiltinState` field and generates the `AppState` impl (`builtins()`/`builtins_mut()`/`source_ports()`/`render_ports()`). Source/render ports of the injected builtin use reserved `PortId` ranges (`SOURCE_PORT_BASE` / `RENDER_PORT_BASE`) so they don't collide with user field ids (which start at 0). `#[derive(Widget)]` auto-skips the injected field (detected by type), so no `#[widget(skip)]` is needed for it.

## Deliberate design decisions — do not "fix"

- **No error handling**: no `Result`/`Error`; unwrap/expect. Panic-fast.
- **No blending, no z-sorting**: `Depth24Plus` with `less_equal`. **Smaller z = closer**. Shared across rect + text passes.
- **Physical pixel coords, y-down**. `Rect::to_ndc(fb: Vec2u)` is the only NDC conversion.
- `Canvas::render()` reads render-slot data from state ports (gpu buffer, bind group, constant). Render slots do NOT own GPU buffers — DAG upload/bind nodes write them into `Option<Arc<...>>` state fields. Fast-path (widget fills/outlines) uses `Canvas::add_instance()` + `set_push_constant()` directly.
- `Material` requires `Eq + Hash + Clone`; registration dedups by value. One pipeline + draw call per material.
- **`#[derive(Widget)]` does NOT generate a `Widget` impl** — it generates `into_viewport_nodes() -> Vec<(String, ViewportNode<Self>)>` and `into_tab_nodes() -> Vec<(String, Vec<(String, ViewportNode<Self>)>)>`. Fields marked `#[widget(skip)]` (e.g. the injected `__builtin: BuiltinState`, render-object ports) are omitted. `into_viewport_nodes()` calls `Self::ports()` internally, so it takes no args and needs no arena.
- **`#[derive(Widget)]` requires `#[derive(DagStruct)]`** on the same struct.
- `Gui.focus: Option<u64>` — direct WidgetNode ID focus.
- `Canvas` is `pub(crate)` — don't expose it or draw helpers.
- Dirty/fired tracking is **hidden inside the graph** (`Rc<RefCell<HashSet<PortId>>>` shared with `DagStructRef`). User code never sees a dirty flag; `Port::write`/`read_mut`/`fire` mark the sets automatically.

## `#[derive(GpuStruct)]` contract

- One trait, one derive. `align(16)` = instance struct (full serialize, real `make_bindings`); no `align(16)` = field type (flat `bytes_of`, `Gpu = sm::Struct<NameGpu>`).
- Wire size differs: instance → div-ceil-16; field → max member alignment.
- Derive also generates `Pod` + `Zeroable` — do NOT hand-write them.
- `serialize` pads grow-only to wire-size boundary.
- `Canvas.clear()` empties fast-path CPU buffers (capacity retained) but skips render slots; GPU buffer grow-only.

## CPU/GPU dual-target system (`dual.rs` + `#[derive(GpuStruct)]`)

**Philosophy: one function, two backends, no relational bounds.**

- `ScalarLike<const GPU: bool>` — scalar + `from_f32`. CPU: `f32`, GPU: `sm::f32x1`.
- `FloatScalar<const GPU: bool>` — `ScalarLike` + arithmetic. Blanket impl.
- `Vec2Like<const GPU: bool>` — 2D vector; CPU `Vec2`, GPU `sm::f32x2`.
- `#[derive(GpuStruct)]` generates `{Name}Like<const GPU: bool>` with one associated type + getter per field, implemented for the CPU struct (`Like<false>`) and GPU twin (`Like<true>`).
- `reinterpret_val`/`reinterpret_ref`/`reinterpret_mut` — `unsafe` bridges between associated types known to be the same concrete type. **Policy: never write relational bounds** (`V1::Scalar = V2::Scalar`); resolve locally with `reinterpret`.
- Reference: `pixel_to_ndc`, `rect_to_ndc` in `dual.rs`; GPU-side call sites in `shader/rect.rs`.

## text / taffy / winit gotchas

- glyphon `prepare_with_depth` per-glyph z via `Attrs::new().metadata(area_index)`.
- **taffy 0.13**: `Dimension` is a struct — `length(f32)`, `auto()`, `percent(f32)`. Query with `is_auto()`/`value()`. `Style` needs `..Default::default()`.
- **taffy widget layout**: primitives put size in `min_size`, NOT `size`. Composite size reads `size` first, then `min_size`.
- taffy `Layout::location` is relative to parent — sum ancestors.
- winit 0.30: `MouseInput` has no cursor position; `Char` skips control chars.
- `crate::math::Vec2` has `x`/`y` only.

## Viewport tree (`gui/viewport/`)

**`ViewportNode<S>` variants** (all generic over the state `S`):
- `Widget(WidgetNode<S>)` — leaf widget.
- `Split(SplitNode<S>)` — two children, draggable divider.
- `Tab(TabNode<S>)` — tabbed panels.
- `Container(Vec<(String, ViewportNode<S>)>)` — labelled vertical table.

- **No `sub_viewport` on `WidgetNode`** — nest via `ViewportNode` variants.
- **Hybrid layout**: Container uses taffy (`container_table_rects`); Split/Tab use pixel arithmetic; Widget renders into its received `rect`.
- **Margin indentation (8px/nesting)**: Split has margin on its axis (`split_margin_rect`); Tab/Container have none.
- **Right-click context menu**: "Split Horizontal"/"Split Vertical" wraps the node in a `SplitNode` with a duplicate. `execute_split` uses `ptr::read`+`ptr::write`.
- `ViewportNode::layout_style(&self, state: &DagStructRef<S>) -> taffy::Style`.

## DAG system (`graph/`)

**Core abstractions:**
- `PortValue: Clone + Default + 'static` — types flowing through ports (f32, u32, bool, String, `()`, `Vec<RectEntry>`, `Vec<TextObject>`, `HashMap<K,V>`, `InstanceBuffer<I>`, any `Material`, structs via `#[derive(DagStruct)]`).
- `PortId(u64)` — field index within a state `S`. Only meaningful relative to its state type (each state numbers fields from 0; injected `BuiltinState` fields use reserved high ranges via the `#[state]` macro).
- `Port<D, S = BuiltinState>` — typed field handle (see "unified state model").
- `PortGroup<S>` — structural group of ports (single `Port`, `()`, tuples 2–4, `{Name}Ports`, `IdGroup`). `leaf_count()`, `extend_ids(&mut Vec<PortId>)`, `ids()`.

**Graph construction (`app.graph_mut() -> &mut Graph<S>`):**
- `Graph::new()` — no args (source/render ports come from `S::source_ports()`/`render_ports()`).
- `graph.add_node(eval, inputs, outputs, condition)` — `eval: FnMut(&mut DagStructRef<S>, Option<&sm::Gpu>)`. `inputs`/`outputs: impl PortGroup<S>`; `condition: Option<Port<bool, S>>` makes it event-driven.
- `graph.add_map_node(map, global_in, global_out, elem_in, elem_out, eval)` — dynamic fan-out (below).
- `graph.with_state(&mut state) -> DagStructRef<S>` — wraps the state, routing writes into the graph's dirty/fired sets (used by `App` to write source fields, and by the GUI render walk).
- `Graph::tick(&mut self, state: &mut S, gpu: Option<&sm::Gpu>)` — runs dirty/condition/new nodes in topo order, then resets fired conditions.

**Execution semantics:**
- New nodes run unconditionally on their first tick, then only when any input port is dirty.
- Condition nodes run **only** when their condition port reads `true` (dirty ignored, no auto first-run).
- `Port<bool, S>::fire(&mut DagStructRef)` writes `true` + marks fired; `Graph::tick` resets all fired conditions to `false` at end-of-tick.
- **Level-triggered sources need rising-edge detection** in the fire node's closure (see `examples/click_rects.rs`).

### Dynamic HashMap fan-out — `Graph::add_map_node`

```rust
graph.add_map_node(
    map,            // Port<HashMap<K, E>, S> — mutated in place
    global_in,      // PortGroup<S> — a dirty global input → full refresh
    global_out,     // PortGroup<S> — topology (global writes)
    elem_in,        // PortGroup<E> — element read ports
    elem_out,       // PortGroup<E> — element write ports
    |gref, gpu, key, eref: &mut DagStructRef<E>| { /* process one element */ },
);
```

- The node **diffs the map against a private `prev` snapshot** each tick, so **only changed keys are reprocessed** and only changed entries are re-allocated in the map. Removed keys are dropped from the output.
- `E: Clone + PartialEq` (needed for the diff). The eval clones each changed element, wraps it in `DagStructRef<E>`, runs the closure, and writes the result back.
- `global_in`/`global_out`/`elem_in`/`elem_out` are **separate parameters** so the graph can distinguish global (`S`) from element (`E`) ports — the two are different types.
- Reference: `examples/dynamic_map.rs` + `tests/dynamic_map.rs`.

**Widget → DAG bridge:** widgets write through `DagStructRef` (`Port::write`), auto-marking ports dirty; the graph re-runs nodes reading them on the next tick. No manual `mark_dirty` wiring.

**DAG-produced custom render objects** (`App::register_render_object`): material + instance buffer + push constant + gpu buffer + bind group are all **declared fields of `S`**. Two internal nodes upload the buffer and build the bind group. Canvas reads them from the state each frame.

## ViewportRect — custom widget rendering (`gui/primitives/viewport_rect.rs`)

`ViewportRect` is a passive data-tap: `Port<ViewportRect, S>` implements `Widget<S>`, and its `render` writes the layout-assigned `Rect` back into the state each frame. A DAG node reads it, converts to NDC, and feeds a custom material's push constant. **One-frame lag** (widget writes during render; DAG reacts next tick → use `compare_snapshot_frame2`). Reference: `tests/snapshot_viewport_rect.rs` + `examples/custom_widget_rendering.rs`.

## Widget layer (`gui/widget.rs`)

- `Widget<S>: 'static + Clone` — `type Data: WidgetData`, `layout_style(&DagStructRef<S>, &Data)`, `render(&mut DagStructRef<S>, &Data, Rect, &mut RenderContext)`, `on_event(&mut DagStructRef<S>, &mut Data, &InputEvent, Rect)`. `self` is the widget handle (e.g. `Port<f32, S>`); read/write through `DagStructRef`.
- Primitive `Widget<S>` impls: `Port<f32, S>`/`Port<u32, S>`/`Port<i32, S>`/`Port<usize, S>` (number), `Port<String, S>` (string), `Port<bool, S>` (bool), `Port<Vec2, S>` (vec2), `Port<ViewportRect, S>` (viewport_rect). All are blanket `impl<S: 'static> Widget<S> for Port<T, S>`.
- `RenderContext { fills, outlines, texts, framebuffer }` — no `add_render_object()`; custom rendering goes through DAG + `register_render_object`.
- `AnyWidget<S>` — type-erased handle + data (fn pointers over `W: Widget<S>`); `WidgetNode<S>` = `AnyWidget<S>` + `id` (no `port_ids` — accessors are in the port, not an id list). `duplicate()` clones the handle with fresh data.

## Testing quirks

- `App::step(inputs, dt, elapsed, cursor, fb_size)` — CPU-only frame simulation; derives `mouse_down`/cursor from `inputs`.
- `AppRunner<S>::after_tick(&AppContext<'a, S>) -> Vec<InputEvent>` — events injected next `step()` (one-frame lag). `AppContext` exposes `state: &S`, `graph: &Graph<S>`, `gui: Option<&Gui<S>>`.
- Snapshot tests are their own binaries; goldens auto-accept on first run.
- Widget unit tests: `DagStructRef::new(&mut state)` gives isolated dirty tracking; call `port.on_event(&mut r, &mut data, &event, rect)`.
- Scene functions must use `app.state_mut()` (not a separate local state) — ports reference `S` by type, and a mismatched state produces the wrong accessors at render time.

## shame EDSL gotchas

- Comparisons are methods: `x.lt(y)`, `x.le(y)` — `x < y` does not compile.
- `shame_wgpu::bind_group!` generates `{Name}Resources`.
- Generated code uses `::shame_gui::...` and `shame::__private::...` — user crates must depend on `shame` directly.
